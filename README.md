# playwright-sdet-kit

Фреймворк автоматизації тестування на **Playwright + TypeScript**, побудований з нуля:
типізований API-клієнт, фікстури, зведені через `mergeTests`, фабрики тестових даних, строгі
`zod`-схеми відповідей із власним матчером, ESLint + Prettier і CI на GitHub Actions.

Зверху — **ланцюжок агентів BA → QA → TA**, який зі специфікації
[RealWorld / Conduit](https://github.com/gothinkster/realworld) виробляє контрактні API-тести.
Кожна передача між агентами лежить у git як диффабельний артефакт, а її форма **перевіряється
кодом**, а не домовленістю.

Агенти нічого не комітять самі — вони виробляють **пропозиції** у `pipeline/`, рішення ухвалює людина.

## Запуск тестів

```bash
npm install
cp .env.example .env      # за потреби — змінити CONDUIT_API_URL
npm run test:contract     # контрактні тести проти Conduit API
npm run test:unit         # тести парсера артефактів ланцюжка
npm run test:defects      # відомі дефекти цілі — червоні за задумом, див. нижче
npm run lint
npm run typecheck
```

Браузер не потрібен: тести працюють лише через `APIRequestContext`.

`.env` не обовʼязковий — без нього береться значення за замовчуванням із конфігу. Він потрібен
лише щоб **перемкнути ціль** на іншу реалізацію специфікації Conduit.

## Три сюїти, три різні питання

| Проєкт | На що відповідає | Коли ганяється |
|---|---|---|
| `contract` | чи код і схеми досі відповідають цілі | кожен push і PR — це ворота |
| `unit` | чи валідатор артефактів ланцюжка працює | там само |
| `defects` | **чи ціль досі зламана** | щоночі за розкладом |

Розвідка знайшла в обраній цілі справжні дефекти — деталі в
[`spec/FINDINGS.md`](spec/FINDINGS.md). Тести на них стверджують **специфікацію**, отже червоні,
і кожен несе посилання на заведений issue. Вони винесені в окрему сюїту, бо відповідають на
питання про **чужий API**, а не про цей код.
